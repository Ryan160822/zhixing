# Mac 桌面被执行人批量查询 APP 设计

## 目标

做一个只给当前 Mac 本机使用的桌面 APP，把现有人工流程自动化：用户批量粘贴个人或企业名单，APP 自动识别类型、逐条查询中国执行信息公开网、在需要验证码时暂停等待人工输入，并把每条查询结果保存为 PNG。

第一版不做公开分发、不做安装包签名、不接入企业信用信息公示系统。

## 使用对象

主要使用者是项目所有者本人。优先保证本机可用、流程稳定、结果文件清楚可归档。

## 输入规则

APP 提供一个批量输入文本框，一行代表一个查询对象。

识别规则：

1. 一行内出现 18 位身份证号时，按个人查询。
2. 身份证号之外的文字按姓名处理。
3. 姓名和身份证号前后顺序都可以。
4. 一行内没有身份证号时，整行按企业名称查询。
5. 空行自动忽略。
6. 无法识别姓名的个人行标记为输入错误，不进入查询队列。

示例：

```text
330000199001011234 张三
李四 330000198805052222
某某建设有限公司
```

## 查询流程

1. 用户粘贴名单。
2. APP 解析为查询队列。
3. 用户点击开始查询。
4. APP 逐条请求中国执行信息公开网综合查询页面。
5. APP 获取本条查询对应的验证码图片。
6. 界面显示放大的验证码图片，验证码输入框自动聚焦，并暂停队列。
7. 用户手动输入验证码，按回车提交当前条。
8. APP 提交当前对象的查询。
9. 查询成功后生成 PNG，删除本条验证码图片。
10. 队列自动进入下一条。

如果验证码错误或过期，当前条目标记为验证码错误，并允许用户重新获取验证码继续查询。

## 界面结构

第一版采用单窗口布局：

1. 批量输入区
   - 大文本框，用于粘贴个人和企业名单。
   - 开始查询按钮。
   - 清空按钮。

2. 验证码区
   - 当前查询对象名称。
   - 放大的验证码图片。
   - 自动聚焦的验证码输入框。
   - 提交本条按钮。
   - 重新获取验证码按钮。
   - 快捷键提示。

3. 队列结果区
   - 序号。
   - 类型：个人或企业。
   - 名称。
   - 身份证号或空。
   - 状态。
   - 输出文件路径。

状态包括：

```text
等待中
等待验证码
查询中
已完成
验证码错误
查询失败
输入错误
```

## 输出规则

查询结果保存到项目目录下的 `results/` 文件夹。

个人文件名：

```text
姓名_被执行人查询结果_YYYY-MM-DD.png
```

企业文件名：

```text
企业名称_被执行人查询结果_YYYY-MM-DD.png
```

PNG 内容沿用当前项目已有样式，包含：

1. 查询网站名称。
2. 查询对象名称。
3. 身份证号或组织机构代码字段。
4. 查询法院范围。
5. 查询结果提示。
6. 查询网站地址。
7. 查询日期。

## 验证码规则

APP 只展示验证码图片和输入框，不自动识别、破解或代输验证码。

验证码图片是临时文件。当前条目查询成功后，APP 删除对应验证码图片。

为了降低人工操作成本，第一版提供快速验证码输入：

1. 验证码图片自动放大显示。
2. 验证码输入框自动聚焦。
3. 用户输入验证码后按 `Enter` 直接提交。
4. `Cmd+R` 重新获取验证码。
5. 验证码错误时，APP 保持在当前条目，提示错误并允许重新获取验证码。
6. 验证码提交成功后，队列自动继续下一条。

## 错误处理

1. 网络请求失败：当前条目标记为查询失败，可重试。
2. 网站返回网络繁忙：当前条目标记为查询失败，可重试。
3. 验证码错误：当前条目标记为验证码错误，可重新获取验证码。
4. 查询返回空结果：生成“没有找到相关结果”的 PNG。
5. 查询返回有记录：生成包含记录表格的 PNG。
6. 输出文件重名：自动追加序号，避免覆盖旧结果。

## 技术路线

第一版采用本地 Mac 桌面 APP。

建议实现方式：

1. Python 负责查询、验证码下载、结果解析、PNG 生成。
2. 本地桌面界面负责输入队列、验证码输入、状态展示。
3. 所有数据保存在本地项目目录，不上传外部服务器。

最终技术选型在实现计划中确认，优先选择依赖少、能快速在当前 Mac 上运行的方案。

## 不做事项

第一版不做：

1. 微信小程序。
2. Windows 版本。
3. 企业信用信息公示系统查询。
4. 自动识别验证码。
5. 用户登录和云端同步。
6. 公开分发安装包。
7. 自动上传查询结果到 GitHub。

## 验收标准

1. 用户能在 Mac 上启动 APP。
2. 用户能粘贴多行个人和企业名单。
3. APP 能正确识别个人和企业。
4. 队列能逐条查询。
5. APP 能显示验证码图片并等待人工输入。
6. 验证码输入框能自动聚焦，用户按 `Enter` 后 APP 能提交查询并继续下一条。
7. 每条成功查询都生成 PNG。
8. 成功查询后验证码图片被删除。
9. 查询结果 PNG 保存在 `results/`。
10. `results/*.png` 默认不进入 Git 提交。
